## The decisions

### SEED POLICY — rule + enforcement machinery (decision 1, the part we can build now)
*🔧 implementable in code now*

**Decision.** Adopt the TIGHTEST-CREDIBLE-FRONTIER rule in VERIFIER-NATIVE units, enforced by a machine-checked positive-signature gate, not a comment convention. seedScoreAtoms_i = ceil( min over ALL public constructions, each scored under THIS problem's own verifier, * 1e18 ). Public constructions = (a) the published record re-encoded into the pinned solution format and re-scored in-format, (b) every repo-bundled witness, (c) every testnet reveal (on-chain DA makes them public forever). The published DECIMAL is demoted to a cross-check only.

**Rationale.** The loss function is asymmetric and irreversible in one direction: a too-loose (too-high) seed mints a false prize the instant anyone replays known work — theft, unrecoverable after claim, and it also dilutes every honest solver via the telescoping denominator — while a too-tight seed merely rejects a genuine sub-seed record at reveal, a missed payout fixable by a pre-funding redeploy. So every tie breaks tighter. The verifier-native reframe closes the units bug the published-decimal rule leaves open: the record lives in the literature's continuum functional, the payout lives in our discretized functional, and erdos proves these differ by ~6e-5 — so porting a public construction can score BELOW a transcribed decimal and mint credit for a straight replay. Scoring everything under our own verifier collapses that gap by construction.

**Implementation.** CONTRACT (canonical redeploy): (1) add `bool public acceptingFunds` to P42BountyPool, default false; `_fund()`/`receive()` revert P42_NOT_ARMED unless acceptingFunds; timelock sets it only after the gate passes — this closes the permissionless-funding hole where a stranger funds an unarmed/mis-seeded problem. (2) deploy script asserts the constructor `seedScoreAtoms` equals the signed dossier value byte-for-byte. CI/REPO: SEED.md per problem with fields {provenance_class: PUBLISHED-RECORD|OPERATOR-WITNESS|IN-HOUSE-BASELINE; exact rational seed + atom encoding; sha256 of the in-format artifact achieving it; verifier-transcript hash; launch_status: FUNDABLE|NEEDS-RESEARCH|HOLD|NEVER-FUND}. CI passes ONLY on a POSITIVE artifact: an EIP-191 signature over (problemId, seedScoreAtoms, sha256(SEED.md)) by a designated key — never on the ABSENCE of a TODO string (that is satisfiable by deleting the confession). Fund-time freshness gate: funding script re-enumerates public witnesses (indexer reveals + repo tree hash) and refuses to fund if anything public postdates the dossier signature or the dossier is >30 days old. Insider rule in FUNDING.md + published addresses: owner, operator, resolver, and dossier reviewers may not claim on a problem they gate. Published-value-without-in-format-witness seeding allowed ONLY with a documented discretization-gap analysis AND the seed set to the published decimal minus one unit in its last printed place (never the raw decimal), AND a 180-day pool sunset so an unreachable seed strands effort only bounded-time.

**Needs a human fact.** None for the machinery itself — the flag, gate, CI signature check, and freshness enumeration are all buildable now. The signing KEY must be designated by the owner.

### SEED VALUES per problem + the erdos genuine-vs-artifact call (decision 1, the part gated on facts)
*🖊️ code-ready; gated on a named human fact*

**Decision.** erdos-min-overlap: seed = the bundled witness's EXACT rational verifier score (~0.3808665), NOT the Haugland decimal 0.380926853433087. This is decision-theoretically dominant: the witness verifies below Haugland under the very verifier that pays out, so under EITHER hypothesis (genuine refinement or discretization artifact) seeding at Haugland lets anyone replay the bundled file and mint ~6e-5 of pool share for zero work; seeding at the witness is safe under both, and the witness then correctly earns zero credit. Per-problem launch verdicts: FUNDABLE-FIRST = erdos (after the pre-funding checks below pass) and hadamard-668-defect (after an indexed baseline pass). NEEDS-RESEARCH = autoconvolution-c1-upper, signed-autoconvolution-c3-upper (moving literature — pin citation + re-verify in-format + standing arXiv watch), mertens-lp-ceiling-k12000 (solve the finite LP in-house; if the gap is negligible the problem is CLOSED, do not fund). HOLD = arithmetic-kakeya (must FIRST prove the certificate space finite; the SPEC states no bound making it enumerable — if finiteness can't be shown it stays HOLD), edges-vs-triangles (pays for denser rational sampling of Razborov's exactly-known curve — respec before any funding). OPERATOR-WITNESS-only, small pools = pnt-sparse-mertens-construction, autoconvolution-c2-lower. NEVER-FUND = hadamard-mini (demo fixture).

**Rationale.** The seed VALUE is the one funding-critical input no policy can synthesize — it is a real-world math fact. The erdos seed choice does not require resolving genuine-vs-artifact because it is dominant under both, but funding erdos DOES require bounding the artifact floor: if the ~6e-5 anomaly is the pinned functional under-measuring the continuum, that anomaly is an optimization surface an adversary harvests down to an unbounded floor. hadamard-668 is the highest wrong-high-seed risk in the portfolio: the Sylvester-prefix 55444 baseline is weak and off-the-shelf annealing will crush it, so its seed must come from a compute pass indexed to pool size, not the bundled baseline.

**Implementation.** Erdos pre-funding tasks (all bounded, all block FUNDABLE): (0) BOUND THE ARTIFACT FLOOR — a budgeted adversarial pass optimizing the pinned n=2400 functional directly from the witness (and from a re-encoded Haugland construction if achievable); if it beats the witness by > 1e-7, the functional is leaking and erdos is NOT fundable until diagnosed. (1) semantic audit of the piecewise-linearity/discretization lemma — does the n=2400 step-function score truly upper-bound the continuum constant. (2) re-encode Haugland's construction in-format and re-score; tightest wins. LEADERBOARD/SPEC label the frontier 'best verified in-format score', never 'improves the Erdos constant', absent a named expert sign-off. hadamard-668: run a baseline search (simulated annealing/tabu from Sylvester/Paley starts) whose compute budget >= the pool value's worth of commodity cloud compute; seed = best in-format score found; publish committed search logs + sha256 of every candidate; all addresses that touched the baseline are barred from the first epoch. hadamard-668 SEED.md uses a 30-day public seed-comment window before instance deploy (no published 'defect at order 668' record exists — two honest reviewers can only attest ABSENCE, so the seed is 'best from published methods' with a public challenge window, NOT a fabricated 'record').

**Needs a human fact.** NAMED FACTS: (a) Kevin signs each SEED.md confirming the value/date. (b) erdos: a qualified mathematician (min-overlap literature) rules on the discretization lemma and reviews the artifact-floor result — a math fact no policy synthesizes. (c) c1/c3: human-verified current-literature citations pulled from the papers, not model memory. (d) hadamard-668 and mertens-k12000: owner approval to spend the compute budget. (e) edges-vs-triangles: owner product decision to respec or keep on HOLD.

### F15 — post-close residual (dust + never-claimed strand)
*🔧 implementable in code now*

**Decision.** CLAIM DEADLINE + FULL RESIDUAL SWEEP at 365 days, PAIRED with a symmetric immutable close-by commitment so neither party controls both ends of the clock. Reject dust-only recovery (fixes N-1 wei, buys an enumerable solver set for nothing) and reject leave-stranded (dead capital, breaks the sweep-to-rollover promise).

**Rationale.** A 365-day pull-payment expiry is fair to the actual solver population — active agents who just ran commit/reveal/finalize can run one more claim() within a year, and the deadline is knowable at close. The deadline collapses 'balance - sum(outstanding)' to 'entire remaining balance', so no on-chain solver enumeration is needed. But the deadline runs from close(), which is owner-discretionary — so without a close-by obligation the owner holds both ends (indefinite pre-close limbo, plus expiry timed to solver inattention with the treasury as beneficiary). The symmetric closeBy fixes that.

**Implementation.** P42PayoutLedger: immutable uint64 claimDeadlineSeconds = 365 days (constructor, floor >= 90d); close() sets closedAt, emits Closed(..., closedAt + claimDeadlineSeconds); consumeClaim() reverts P42_CLAIMS_EXPIRED after the deadline; permissionless sweepResidual() requires closed && now > closedAt + deadline && !residualSwept, then pays the pool's full remaining balance to treasury and sets residualSwept (one-shot). Define ordering so sweepFee() is satisfied first (or fold feeReserve into the sweep) — property test: after sweep, pool balance == 0 and no claim path succeeds. CRITICAL EDGE: handle totalCreditAtoms == 0 (e.g. the canary) — finalEntitlement is 0 for all, so sweepResidual must recover the whole distributable, not just dust; verify this case on Sepolia first. SYMMETRIC COMMITMENT: each pool declares an immutable closeByTimestamp at deploy (e.g. fundedAt + 2y, floor >= 180d); after it, close() becomes PERMISSIONLESS subject to the existing openSubmissionCount == 0 guard (open submissions clear permissionlessly via expireCommitted/expireRevealed). Emit closeBy in the funding event; publish both terms in FUNDING.md/SPEC.md/UI before any real-ETH funding: 'this pool closes no later than X; after close you have 365 days to claim.'

**Needs a human fact.** Counsel memo (already a real-ETH gate) must cover prize forfeiture / abandoned-property law for 'unclaimed prizes revert after 365 days' in the operating jurisdiction. The 365d/2y figures are ours; their lawfulness is the human fact.

### F16 — commit-spam DoS on close()
*🔧 implementable in code now*

**Decision.** NO new anti-spam contract mechanism. Keep commit() permissionless; pin real-ETH params alphaBps and a real bond floor; make a corrected SCHEDULED-CLOSE runbook the standing defense. Per-sender caps are sybil theater (addresses are free); escalating bonds punish honest frontier-race bursts more than sybils.

**Rationale.** Spam only attacks close(), an end-of-life action; mid-life spam blocks nothing and forfeits its bond to the treasury. The audit's own verdict is that pause-then-close fully mitigates. BUT the naive runbook is actively harmful in three verified ways, and the real threat is 3x mispriced: (i) pausing the LEDGER blocks honest finalize because recordCredit reverts when paused — seizing the bonds/credit of exactly the solvers racing the frontier; (ii) reveal() is deliberately un-paused, so an attacker commits at T-1s then reveals garbage at commit+72h-e claiming a near-max improvement, holding close hostage ~9 days per bond, not 80h; (iii) a 2%-of-pool commit bond is exactly enough to pass finalize's bond-covers-entitlement check, so an unchallenged fraudulent reveal FINALIZES and captures nearly the whole pool — meaning the operator MUST challenge every invalid reveal, and the binding cost is challenge float + resolver liveness, not commit counts.

**Implementation.** Pin: alphaBps = 200; minPostingBondWei = 0.01 ETH (NOT the 0.0001 demo value); challengeWindowSeconds = 72h (7d for the pilot only). Fixed runbook (INCIDENT_RESPONSE.md + timelock batch template): (1) T-7d announce close on-chain + UI. (2) T-0 pause ONLY the SubmissionManager (blocks new commits; leave the ledger LIVE so in-flight reveals can finalize; consumeClaim is unaffected). (3) publish T-0 as 'last commit' and T+144h as 'finalize deadline'; budget close for T+152h nominal, T+~226h worst case. (4) SLO: within 12h of any reveal whose claimed score the operator's verifier run does not reproduce, file the challenge — this converts the 216h tail into one resolver round-trip and is the ONLY thing between a 2%-of-pool bond and full-pool theft. (5) pre-fund an operator challenge float = 3 x requiredChallengeBond(distributablePool); add resolver time-to-resolve to runner alerts. (6) split cleanup: expireCommitted freely for never-revealed spam; expireRevealed ONLY for operator-verified-invalid or past-finalize-deadline submissions — never a bulk sweep (finalize is solver-only; a bulk expire seizes honest bonds). (7) re-key the spam alert to reveals claiming > 10x the historical best marginal (the dangerous pattern), not commit counts.

**Needs a human fact.** None to decide. The named operator + on-call resolver who run the SLO are already an irreducible path-to-live gate, not new here.

### F17 — guardian veto / permanent-halt risk
*🖊️ code-ready; gated on a named human fact*

**Decision.** Two-layer fix with four amendments that survived the attack. (1) guardian = a 2-of-3 Safe, signers DISJOINT from the timelock signers (address-level K-of-M, zero base contract change). (2) add an override-class op the guardian cannot indefinitely block: threshold = ceil(2N/3) (4-of-5 on a 3-of-5 base) and 2x delay (96h), used for signer/guardian rotation and as the fallback for any op a hostile guardian cancels. AMENDMENTS: (a) op lifecycle — EVERY op expires at eta + 7d grace (today ops never expire, so an override op with malicious calldata that the guardian cannot cancel would be a permanent brake-free grenade any anon could execute forever); a signer MAJORITY (3-of-5) can self-cancel any op including override-class. (b) guardian brake on overrides is BOUNDED to at-most-once per opId-family = hash(target, data) only (not salt, to defeat salt-mining) — preserves a brake against a 4-key compromise while capping a hostile guardian to one extra 96h delay, not a halt. (c) signer rotation (add/remove/swap) via timelock self-call reachable only through override-class ops, with threshold auto-revalidation and an invariant test that removal can never make overrideThreshold > signerCount (today signers are constructor-only, so losing 2 of 5 keys — the likeliest multi-year event — permanently bricks the override and restores absolute guardian veto). (d) an unvetoable fast-PAUSE: a dedicated Pauser role (any single timelock signer or a named pauser key) calls setPausedNewActions(true) DIRECTLY on managers, never entering the timelock, so a compromised guardian cannot veto an emergency pause and outlast a 72h challenge window; unpause stays a standard timelocked op.

**Rationale.** Verified: cancel() is guardian-only + always wins (re-schedules restart the delay), guardian and signers are immutable, execute() is permissionless once confirmed + ops never expire. So a lost/compromised guardian is a PERMANENT halt with no rotation and immutable-owner children that can't migrate. The override converts 'permanent halt' into '(assemble 4-of-5) + 96h public window'; op expiry + signer self-cancel kill the uncancellable-grenade the naive override introduces; signer rotation kills the lost-key re-brick; the fast-pause kills the hostile-guardian-outlasts-the-72h-window race.

**Implementation.** Timelock v2 (in the canonical redeploy, in the audit scope): base N=5 threshold=3 delay=48h; scheduleOverride(target,value,data,salt) sets eta = now+96h and requires confirmations >= max(threshold+1, ceil(2N/3)); cancel() reverts for override-class AND is capped one-per-family for standard ops; every op -> Expired at eta+7d; self-cancel by 3-of-5; addSigner/removeSigner/swapSigner + setGuardian are timelock self-calls reachable only via override; Pauser role wired to managers' setPausedNewActions. Invariant tests: guardian can cancel a standard op once but not twice per family; guardian cannot block an override past 96h; 3-of-5 cannot execute an override; removal can't invalidate the override threshold; Pauser pauses without the timelock. PILOT RIGHT-SIZING: for total exposure <= 2 ETH, run 2-of-3 timelock + ONE guardian key held by a distinct person, disclosed in SECURITY.md as 'centralized training wheels', with a hard codified escalation trigger (protocol TVL > 5 ETH OR > 3 funded problems OR Phase-3) at which 3-of-5 + 2-of-3-guardian-Safe becomes mandatory — reachable BECAUSE v2 has signer rotation, so escalation is a signer-set change not a redeploy.

**Needs a human fact.** NAMED HUMANS: the timelock signers and the guardian holder(s), hardware wallets, guardian set organizationally independent of signers, plus the legal entity behind the multisig. We decide thresholds; we cannot name the people. Pilot needs 4 genuinely distinct humans (Kevin + 2 signers + 1 guardian); the 8-person structure is the scale gate, not the pilot gate.

### F12 — freeze un-latch when a funded pool drains to zero
*🔧 implementable in code now*

**Decision.** One-way everFunded flag read by the registry, PLUS contract-enforced freeze-before-fund (not a script assert). Reject the derived-from-live-balance freeze (re-opens the anchored spec after drain) and reject runbook-only ordering (the one control a rushed/compromised operator skips, and a 1-wei grief can latch a spec the owner never signed off).

**Rationale.** isFrozen() deriving from pool.funded() > 0 means the anchored spec/verifier hashes re-open to owner mutation after close+claims drain the pool — corrupting the immutable historical record and enabling a verifier-hash swap. everFunded makes the latch monotone from the first wei. But fund()/receive() are permissionless, so a griefer sends 1 wei to each new pool and permanently freezes DRAFT specs (wrong verifier hash, typo) before the owner's review window, forcing a per-problem redeploy loop at ~zero cost. Making the pool require the registry's EXPLICIT frozen bool before accepting funds turns the 1-wei grief into a revert and makes freeze-before-fund an on-chain invariant.

**Implementation.** P42BountyPool: add `bool public everFunded`; _fund() sets it true once; AND _fund()/receive() require registry.problems(problemId).frozen == true (the owner's EXPLICIT bool, not the derived isFrozen()) else revert P42_NOT_FROZEN — no circularity (pool reads the explicit flag; registry's derived isFrozen() reads the pool's everFunded). P42ProblemRegistry: isFrozen() returns problem.frozen || pool.everFunded(); retarget the existing permissionless latchFrozen() to everFunded. This composes with the acceptingFunds flag from the seed gate (both must be true to fund). Forced ETH via selfdestruct bypasses fund() but also bypasses funded() accounting, so it latches nothing. Tests: fund() before freeze() reverts; 1-wei direct transfer does not set everFunded; fund() after freeze() keeps isFrozen()==true through drain-to-zero and setProblem reverts.

**Needs a human fact.** None.

### POISONED-FRONTIER RECOVERY (decision 6)
*🔧 implementable in code now*

**Decision.** Ship a submission-anchored, timelock-only voidFinalize with NO governance-chosen numbers — do NOT accept pause+redeploy (the pool has no drain, so a poisoned funded pool's ETH strands forever) and do NOT ship a free-parameter raise (a compromised timelock could raise past honest scores and debit honest credit while every require passes).

**Rationale.** The frontier telescopes exactly: totalCreditAtoms == seedScoreAtoms - bestScoreAtoms. Any recovery must pair each atom of raise with an equal ledger-credit void or it either double-pays future solvers or strands share. The safe form binds the void to a SPECIFIC finalize instead of a governance-supplied newBest/voidAtoms pair: the contract enforces 'undo exactly this finalize', and the only human input is WHICH submission — reviewed during the timelock delay. This also composes with the seed ceiling automatically by monotonicity (prevBest <= seed always).

**Implementation.** Canonical redeploy: STORE per finalize (prevBestScoreAtoms, creditAtoms, solver) in the SubmissionManager (today creditAtoms is only EMITTED, so this is a required storage add). Add voidFinalize(uint256 submissionId), timelock-only, requiring: pauseAll mode set (a NEW mode distinct from pausedNewActions that gates commit, reveal, AND finalize — pausedNewActions only gates commit, so under it a fraudster pipelines reveals/finalizes during the timelock window and moves bestScoreAtoms, staling any equality check); no submission in Revealed or Challenged status; and bestScoreAtoms == submissions[id].scoreAtoms (only the CURRENT frontier-holder is voidable; stacked frauds unwind newest-first by repeated calls; a poisoned problem has no later finalizes since every subsequent reveal yields zero credit). It sets bestScoreAtoms = stored prevBest and adds a P42PayoutLedger.voidCredit(solver, storedCreditAtoms) (creditRecorder-only, requires creditAtomsOf[solver] >= atoms, reverts if closed). While pauseAll is set, expireCommitted/expireRevealed revert (or toll by paused duration) so honest in-flight commits made during the poisoned window are NOT forfeited — the corrected disclosure is re-reveal latency, no honest bond burn. voidFinalize is schedulable as an OVERRIDE-class op (4-of-5 + 96h) as the fallback when a hostile guardian cancels the standard attempt — combined with F17's one-cancel-per-family bound, a hostile guardian buys 96h, not a brick. Never close() a problem with an open frontier dispute (close is itself timelocked = a second checkpoint). Accepted, disclosed loss: the fraudster keeps their returned posting bond (no pool ETH moved pre-close); if they already claimed post-close, the paid ETH is gone — no clawback power added.

**Needs a human fact.** The fraud determination itself pre-Phase-3: a named resolver/operator must publish a reproducible verifier transcript showing the finalized bytes do not reproduce the claimed score, BEFORE the timelock op is scheduled. The contract enforces only the arithmetic; the finding of fraud is human.

## The smallest safe first real-ETH step
